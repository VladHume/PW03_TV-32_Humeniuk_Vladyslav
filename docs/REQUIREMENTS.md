# Відповідність завданням

## Заняття 9: Repository і Data Source

Репозиторій об’єднує локальний DAO та віддалений контракт MonitorApi. Екрани працюють через ViewModel, тому зміна джерела не потребує SQL або HTTP-коду в Compose. Пошук і сортування доступні вже з PW02; Room використовується як постійний локальний кеш віддалених даних.

Реалізація: `data/Data.kt: MonitorRepository`.

## Заняття 10: REST API і JSON

Retrofit описує POST login/register і GET measurements. Gson перетворює JSON на моделі. У застосунку OkHttp interceptor реалізує автономний mock API; інтеграційний тест виконує справжній HTTP-запит до локального MockWebServer. 

Реалізація: `data/Data.kt: MonitorApi; HttpIntegrationTest.kt`.

## Заняття 11: Токен і ролі

Mock API видає випадковий токен і перевіряє Authorization: Bearer. Оператор змінює записи, спостерігач переглядає їх. Невірні облікові дані та доступ без токена повертають HTTP 401. Новий навчальний користувач отримує роль спостерігача. Токен зберігається локально та автоматично додається interceptor. expiresAt задає строк дії; і клієнт, і mock перевіряють завершення сеансу. Це навчальна схема, не production-система автентифікації.

Реалізація: `DemoApiInterceptor; MonitorViewModel`.

## Заняття 12: Помилки та повторні спроби

Доступні сценарії успіху, відсутності мережі, HTTP 503 і пошкодженого JSON. Snackbar показує помилку, а журнал містить її клас без токена чи пароля. Тимчасові збої допускають до трьох спроб, HTTP 4xx не повторюється. Помилки також записуються у внутрішній errors.log: лише час, клас помилки та HTTP-код, без пароля й токена.

Реалізація: `MonitorViewModel.task, sync`.
